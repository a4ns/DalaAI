## Воспроизводимый запуск доступной основы

Команды ниже взяты из существующих `Makefile`, `ops/README.md`,
`ops/smoke.py` и ASGI entrypoint. Команда в инструкции не равна её выполнению:
результаты смотрите отдельно в ledger. Выполнять из корня checkout.

### 1. Зафиксировать код без чтения секретов

```sh
git rev-parse HEAD
git status --short
sha256sum coord/proposals/a6-contract-v1/contracts/openapi.yaml
make help
```

Сверьте HEAD с выбранным кандидатом. При другом HEAD не объявляйте этот ledger
его проверкой. Не открывайте `.env`, PIN, пароли, токены или документы с ними
без отдельного разрешения владельца; не выводите environment/DSN целиком.

### 2. Проверки без БД

Нужны Python 3.12 и зависимости из существующего lockfile. В собственной
изолированной среде установки предусмотрены реальные команды:

```sh
make install
make check
```

`make install` создаёт `.venv`, устанавливает `backend/requirements-dev.lock`
и выполняет `pip check`. `make check` запускает syntax, backend unittest и
contract-check. Здесь нет существующих `make seed`, `make eval`, `make e2e`,
`make package` или `make deploy`; не выдавайте целевые названия из плана за
доступные targets. Возможные skipped DB-тесты не являются PASS PostgreSQL.
Не запускайте общий aggregate параллельно работе интегратора.

### 3. Только процесс и отрицательная readiness, без БД

В терминале A, с уже установленными зависимостями:

```sh
env -u DATABASE_URL PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=backend \
  .venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 18606
```

В терминале B:

```sh
make smoke-unready BASE_URL=http://127.0.0.1:18606
```

Если зависимости уже предоставлены средой, допустима явная замена
`.venv/bin/python` на проверенный `python3`; зафиксируйте реальные версии
в evidence. Порт должен быть свободен и выделен этому прогону. Не завершайте
чужой процесс, чтобы освободить его. После прогона остановите только свой
Uvicorn через Ctrl+C в терминале A.

Ожидание: `/healthz` — 200 `{"status":"ok"}`; `/readyz` — 503
`{"status":"not_ready"}`. Это успешный отрицательный инфраструктурный тест,
а не готовность БД. `/api/v1/orders` в default app не должен неожиданно
объявляться работающим вертикальным срезом.

### 4. API + PostgreSQL через Compose: только после разрешённой настройки

Нужны Docker Engine + Compose v2 с `up --wait`. `make dev` создаёт локальную
игнорируемую конфигурацию, если её нет, и может сохранить новый пароль
синтетической БД. Сначала получите требуемое разрешение на создание/сохранение
такой конфигурации; C-106 её не создавал, не открывал и не запускал Compose.
Для отдельного checkout/Compose project, после одобрения:

```sh
COMPOSE_PROJECT_NAME=naryadai-demo-c106 API_PORT=18606 make dev
make smoke BASE_URL=http://127.0.0.1:18606
COMPOSE_PROJECT_NAME=naryadai-demo-c106 make down
```

Это существующие targets с изолированным project name и API-портом.
Успешная readiness означает только `SELECT 1`, без доказательства миграций,
least-privilege роли, логина, заказов или frontend. `make down` сохраняет
volume. Не используйте `down -v`, reset, удаление схем или чужую БД.
Для отдельной проверки persistence см. существующий
[ops/PERSISTENCE_VALIDATION.md](../../ops/PERSISTENCE_VALIDATION.md): её
синтетические DB-проверки и профиль роли — отдельные gates, а не браузерное демо.

### 5. Переход к пользовательской демонстрации

Для текущего SHA путь мастер → исполнитель → результат → решение → отчёт
не запускается одной из команд выше. Не изобретайте login/seed/upload-команды,
демо-аккаунты, URLs или HTTPS-деплой. Для live-версии оператор получает от
интегратора точный SHA, реально смонтированный same-origin API/frontend,
изолированную БД и синтетический набор, учётные записи через защищённый канал,
а также фактические команды запуска и проверки. Затем C5 проверяет собранный
путь, и оператор заполняет отдельный device ledger. До этого основной питч
использует явно ограниченный технический вариант.

## Правила показа данных и API

- На всех данных видна пометка «Синтетические данные». Исторический экспорт
  не отправляется как live POST: просроченные даты не разрешают ослаблять
  live-валидацию дедлайнов. Для live создаются свежие наряды согласованным способом
- Пустой `assessments` означает отсутствие оценки, а не pending/failed.
  Отсутствующий human score не превращается в AI score или ноль
- `queue_count` считает только queued; это не общее число задач и не доступность
  человека. `active_order_id` — lowest-number представитель видимых
  in_progress/paused; таких нарядов может быть несколько
- Scoped keyset paging не обещает cross-page snapshot или согласованный total
- Master/manager видят свои каталоги; executor — себя; admin не получает
  workload-строки только по названию роли
- В режиме `rules_fallback` семантика работ, пригодность материалов и содержимое
  фото не оценены моделью. Процент пройденных gates не является качеством ремонта
- Финальное производственное решение принимает мастер; UI/AI не подменяют его

## Если что-то не работает

| Сбой | Действие и честная формулировка |
|---|---|
| Нет frontend/смонтированного API | Перейти к текущему техническому питчу: «Показываем основу; сквозной мобильный путь не проверен» |
| Потеря сети до отправки | «Не отправлено»; сохранить форму в пределах реальных возможностей UI. Это не тест потерянного ответа после commit |
| Ответ потерян после возможного commit | «Результат не подтверждён»; повтор того же payload и operation ID только штатным UI, затем проверить единственный эффект; не создавать новый ID |
| 409 / другой мастер изменил наряд | Загрузить актуальную версию, объяснить конфликт; не затирать чужое изменение |
| Модель недоступна | Показать реальный `rules_fallback` и неизвестный общий score; synthetic provider не объявлять внешней моделью |
| Фото не загрузилось / не прошло проверку | Показать ошибку и обязательность evidence; не заменить подтверждённый upload локальным preview |
| Push запрещён / телефон не получил | Отдельно отметить ограничение; запись job/sent или экранная плашка не являются физической доставкой |
| Демо-состояние не подготовлено | Не делать скрытый reset. Показать маркированный заранее сохранённый материал только при наличии проверенного артефакта |
| Запись видео вместо live | Объявить «запись», SHA и дату; видео пока NOT_RUN и отсутствует в этом пакете |

Не вставляйте fake API success, не выдавайте макет за приложение и не ставьте
самостоятельный «балл готовности». Ни один резерв не закрывает пропущенный gate.
Новые платные API, ключи, внешние уведомления, деплой и подача сюда не входят.
