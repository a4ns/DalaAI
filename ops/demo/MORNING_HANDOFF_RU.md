## Требует человека утром

Выбрать хост и расходы, подготовить Docker/DNS и обычный доверенный HTTPS,
внести секреты через приватный механизм, передать два тестовых PIN операторам.
Для живых уведомлений нужны VAPID-настройка и разрешение браузера; для модели —
разрешённый ключ. Затем пройти проверку на двух физических телефонах ниже.
Публичного адреса сейчас нет.

## Перед 15-минутным запуском

Нужны выбранный сервер, установленный Docker Compose, свободные порты и домен,
если приложение будут открывать телефоны. Первая загрузка образов может занять
дольше 15 минут. Для Render отдельно согласуются платные ресурсы и диск;
его инструкция находится в [ops/managed](../managed/OPERATOR_15_MIN.md).

Выберите профиль **до первой инициализации**:

- `minimal`: два действующих тестовых пользователя и пустой список нарядов
- `history`: те же два пользователя плюс 540 исторических записей; мастер видит
  четыре участка, исполнитель один. Исторические сотрудники не получают вход
- Необязательные часы включаются только для нового профиля. Уже созданная база
  не получает эту возможность автоматически; переключение профиля не сбрасывает
  и не «чинит» существующую базу

Для рекомендуемого **нового** демо с историей и общими часами:

```sh
DALA_DEMO_FIXTURE_MODE=history DALA_DEMO_CLOCK_ENABLED=true ./ops/demo/run.sh
```

Запускайте из нового checkout с новой приватной конфигурацией и новой выделенной
базой/томами. Стандартный launcher использует проект `dalaai-demo`: новая папка
репозитория сама по себе не изолирует уже существующие Docker volumes. При
обнаружении существующей базы без соответствующей приватной конфигурации запуск
остановится. Это не команда сброса. Существующий профиль сохраняется, и попытка
изменить его режим будет отклонена. Для нового профиля без часов оставьте
`DALA_DEMO_CLOCK_ENABLED` выключенным; для пустого списка оставьте режим `minimal`.

История и часы могут быть выбраны вместе для нового профиля: совместный сценарий
проверен в managed-образе. Обычные Compose-проверки отдельно покрывают history
без часов и minimal с часами. Ни один из этих запусков не является публичным хостингом.

Для выбранного публичного VPS задайте перед первым запуском `DALA_DOMAIN` с его точным доменом,
`DALA_BIND_ADDRESS=0.0.0.0`, `DALA_HTTP_PORT=80`, `DALA_HTTPS_PORT=443`.
DNS и обычный доверенный TLS должны работать до проверки телефонов. Не обходите
предупреждения браузера и не считайте локальный тестовый сертификат публичным TLS.

Команда готовит приватную конфигурацию на выбранном хосте. Имена входа:
`DALA-DEMO-MASTER` и `DALA-DEMO-EXECUTOR`. PIN находятся в приватных файлах
`ops/demo/.local/master_pin` и `executor_pin`; не помещайте их в Git, видео,
общие логи или публичную переписку. Повторный запуск сохраняет эти значения.

## Проверка на двух физических Android за 10 минут

Это план проверки, а не обещание измеренной скорости.

1. Откройте один доверенный HTTPS-адрес в двух отдельных браузерных сессиях.
   Войдите мастером и исполнителем, убедитесь в разных ролях
2. Мастер выдаёт новый синтетический внеплановый наряд со сроком в будущем. Исполнитель
   находит именно его, принимает и начинает; мастер видит подтверждённые изменения
3. Исполнитель делает или выбирает безопасное тестовое фото, заполняет результат
   и отправляет его. Не подменяйте загрузку заранее внесённой записью в БД
4. Дождитесь сохранённой рекомендации. Без ключа это явно обозначенные правила.
   Мастер отдельно принимает работу или возвращает на доработку
5. Перезагрузите обе страницы: состояние и фото должны сохраниться. Проверьте
   запрет доступа к отчётам для исполнителя и отсутствие чужих данных
6. Если заранее подключён Web Push, проверьте разрешение пользователя, подписку
   и фактическое уведомление на втором телефоне. Отсутствие разрешения или
   доставки запишите как ограничение, не заменяйте его показом карточки в приложении
7. В новом профиле с часами проверьте паузу, шаг и возврат к 1×. Подготовьте и
   сохраните PDF/XLSX, откройте их обычным приложением телефона. Этот шаг проверяет
   физическое устройство и его системное сохранение, которых не было в CI

Запишите SHA, устройство, браузер, реальный адрес, время, задержки и результат.
Не снимайте PIN, cookie, CSRF, приватные настройки и административные консоли.

## Модель и уведомления

Нормальная подготовка создаёт одну политику именованного демо. После защищённой
настройки `OPENAI_API_KEY` и перезапуска worker выбирает модель автоматически;
без ключа остаются правила. Дополнительный обязательный флаг включения модели
не нужен. Текст и выбранные фото могут передаваться OpenAI; используйте только
разрешённые демонстрационные материалы. Общий предел — $50, до 09:00 UTC+5 —
$10; один постоянный журнал расходов сохраняется между перезапусками. Эти
пределы не являются доказательством выполненного вызова или качества модели.

Web Push требует отдельной человеческой настройки VAPID и разрешения браузера.
Пока провайдер выключен, worker сохраняет задания и не объявляет доставку.
Telegram остаётся отдельным необязательным адаптером; наличие его исходников не
означает, что стандартный Web Push-профиль уже отправляет сообщения в Telegram.

## Если проверка не прошла

Сохраните базу, фото, приватную конфигурацию и журнал расходов. Не запускайте
повторное заполнение, не меняйте профиль и не удаляйте Docker volumes ради
зелёного результата. Запишите конкретный шаг и безопасный код ошибки. Остановка
контейнеров через `down` без `-v` сохраняет данные. Команды сброса данных в
приложении нет.
