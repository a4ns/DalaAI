# Запуск DalaAI: три координатора и 18 исполнителей

Эти инструкции объясняют будущий запуск. Подготовка документа сама по себе не запускает агентов и не создаёт доступы. «Подключить ещё 14» означает открыть ещё два отдельных dot у людей B и C: в каждом координатор плюс до шести рабочих. Это три независимые команды с общим репозиторием, а не одна сеть из 21 агента.

## Перед стартом

1. Общий репозиторий команды DalaAI: **https://github.com/a4ns/DalaAI**. Он публичный по решению владельца. Продукт называется «НарядAI», выбран кейс №1. Не публикуйте персональные данные, секреты и исходный архив конкурса.
2. Владелец сообщил, что выдал доступ двум коллегам. Принятие приглашений и фактические права каждого аккаунта ещё нужно проверить: каждый человек B/C подключается своим аккаунтом и отдельно подтверждает необходимые доступы. Пароли, PAT, API-ключи и OAuth-сессии не пересылаются между людьми и dot.
3. Согласуйте единый commit с принятым комплектом инструкций. Человек A копирует его полный SHA из GitHub и сообщает всем как `<BASE_SHA>`. Не используйте SHA начального README вместо commit, где есть AGENTS.md и START_HERE.md. Пока комплект находится в draft PR, он не считается принятым; merge требует отдельного решения владельца. Все три команды читают одну версию правил. Контракт приложения пока не создан; придуманный contract SHA запрещён.
4. В каждом аккаунте проверяются доступные слоты, выбранная среда исполнения и конфигурация модели. Цель: координатор + шесть рабочих с Astra xhigh; пока доступность и применённый профиль не проверены, 21 одновременно работающий агент не считается подтверждённым.
5. A/B/C по очереди вставляют ниже свой запрос, заменив `<BASE_SHA>` точным согласованным SHA. Координаторы сначала отвечают READY либо BLOCKED. Человек A собирает три ответа, сверяет URL и SHA, затем передаёт каждому явное «Старт согласован». До этого нет кодовых изменений и параллельного запуска рабочих.
6. С первой волны каждому рабочему выдаётся отдельная готовая задача, ветка/worktree и lease. Если готовых независимых задач меньше шести, остальные слоты остаются свободными. Люди переносят короткие межкомандные пакеты и ссылки; никакой несуществующий межаккаунтный agent bus не подразумевается.

READY-пакет: `роль; repo URL; base SHA; версия AGENTS; contract SHA либо «не создан»; среда; доступ на чтение/запись и способ его проверки; доступные слоты; requested/effective model+effort либо «не подтверждено»; blockers`.
