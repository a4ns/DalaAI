# Optional business/demo clock controls

Separate candidate from frontend `859e3c43a545320cfb1fa2bb58b54bb73b853900`, under [A0-0064](https://github.com/a4ns/DalaAI/issues/2#issuecomment-6049373867). Existing analytics/C110/C112 pins are not changed.

Backend source inspected at `b2eda8c2537f1f0ed78583038d69964ee23b6107`; clock/mount bytes also match `d4a2932`. Actual service is GET/POST `/api/v1/demo/clock`, without query parameters. The current runtime authorizes its explicit existing master allowlist; the UI does not contain that list or infer permission from the master role. Only an authorized, validated GET snapshot enables controls.404 means absent/disabled and403 means denied. No synthetic fallback clock is created.

The snapshot includes instance/version, scale, real/domain anchors and sampled times, domain limit, storage mode, `reset_supported:false` and limits60/3600. Pause sends `set_scale:0`; resume explicitly sends1×. Speed is bounded to integer1–60 in its form, forward advance to integer1–3600 seconds. The server owns the cumulative horizon. The display remains a dated server snapshot; no local ticking or inferred domain clock is added. Real authentication, sessions, photo TTL, request/worker/provider timeouts and budgets remain real-time systems.

A control body contains exactly `instance_id`, `expected_version`, `action` and `scale` or `seconds`. There is no operation UUID, receipt endpoint or idempotent replay contract. Preparation freezes the current snapshot and serialized intent. A token is sent at most once, and repeated execution only returns its original promise, including rejection. A direct successful POST must bind to the captured instance and next version/action result; it cannot roll back a newer read.

An ambiguous POST blocks further mutations for this mounted session controller. Separate GET remains available but never proves the original effect failed/succeeded and never clears that lock. No POST replay/adoption control is offered in this narrow increment. A known409 allows only an explicitly started fresh read followed by an explicit acknowledgment before a new intent. The controller is owned by App's authenticated session boundary and stays mounted across tab navigation and unrelated order-list403/recovery. Workspace access gates cannot discard its unknown intent. Logout/epoch changes fence responses and clear this session's private UI state; no pending command is persisted or automatically sent later. The existing logout warning and best-effort beforeunload guard disclose the memory-only limitation.
